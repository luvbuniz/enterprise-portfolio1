01 · The Problem

Kids don't file bug reports. They just stop playing.

Stackadoo is a kids' math and building game (stackadoo.com and the Android app). I built it with AI coding agents.

That's fast, but it creates bugs and UI clutter, and I couldn't replay every screen after every change.

When a kid gets stuck, they don't tell you. They close the app. I needed a tester who notices what a 7-year-old notices.

02 · The Setup

Two lenses, every session

Pip plays and reports, but doesn't ship code. Cobble turns findings into fix briefs and PRs and checks back with Pip. Riley routes the work. Cody hands bigger fixes to ChatGPT/Codex or Claude.

LensWho Pip pretends to beWhat it catches
Kid lensA 7-year-old first-timer. Taps the shiny thing, skips long text, freezes if the next step isn't obvious.Confusion, dead ends, scary or unclear moments
Pro lensAn adult QA tester and parent-teacher.Grading bugs, layout breaks, settings that don't stick
  • Every finding is tagged kid-UX, adult-bug, or both.
  • Focus areas: first-run scaffolding, house and stairs interiors, and pet-shop "buy everything" spam.
  • Report up, don't ship.
  • No faked metrics. Pip must never pad Google Play closed-test engagement.
  • Hands off real players' data. My kids' account is look-only.

03 · The Steps

How it runs, step by step

  1. Wrote the dual-lens brief: personas, tags, and focus areas.
  2. Sep 2: a full dual-lens playtest of the web game. Setup, Math Meadow, Reading Town, building, shops, and quizzes, with screenshots of every step. 17 findings, ranked by severity.
  3. Top priorities: the quiz showing "Oops" on correct answers (8×8→64, 5+54→59, 34−15→19), the reward screen racing the next question, a scary "Gloomies" mode that was on by default and didn't stay off, and Quit hidden behind a hamburger menu a 7-year-old won't find.
  4. Cobble turned these into fix briefs. Fixes shipped as GitHub PRs #482–#486.
  5. Pip verified on the branch before merge, then again live. It caught one case (15÷3→5) still failing live, and Cobble hardened the fix. Final live batch: 80/80 correct answers graded Correct. Pip also confirmed the visible Leave button, a sticky Next button, and 16 starter blocks.
  6. Moved testing onto a real phone: DroidPilot (a phone-control MCP server + Android app) on a Samsung Galaxy S24 Ultra, reached over Tailscale. Pip read the on-screen UI tree and took screenshots.
  7. Sep 7 phone-only findings: the app ran inside a browser custom tab (kids could see browser chrome), a cluttered saved-game list pushed NEW GAME below the fold, a kid could land with 0 blocks and a build tip they couldn't act on, a truncated objective tip, and unclear purple floor cubes. No crashes.
  8. Sep 12 clutter passes at Pixel 7 (412×915), 768px, 1024px, plus iPad Mini: competing hero buttons, nav wrapping, no phone menu, clipped card rails. In-game build 287 had a crowded HUD, NPC bubbles over the paint palette, an intro bubble covering controls, a busy shop, and the canvas filling half the iPad screen.
  9. Routed each clutter brief to the right fixer: Claude for the HUD, Codex for landing-page items.
  10. Ran the Play Console routines during closed testing: daily install tracker, reminders, reciprocal cleanup.
  11. QA'd partner apps too, and found real bugs for other developers: a launch crash from a test API key, a country block, and missing US units.
